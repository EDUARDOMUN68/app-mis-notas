# Arquitectura

Interfaz estática sin dependencias. `dist/index.html` y `style.css` definen la interfaz; `app-1.1.0.mjs` controla eventos y mensajes (la entrada anterior se conserva para HTML antiguo en caché); `model.mjs` valida, interpreta entradas y persiste el estado. Servicio opcional de avisos independiente con web-push en `notifications/`.

Un único registro JSON incluye revisión, tareas con identificadores estables y compositor (texto y categoría). Cada escritura comprueba la revisión anterior y verifica la lectura posterior. Un fallo conserva el estado confirmado en pantalla y muestra un error. Un cambio desde otra pestaña bloquea la edición hasta recargar para evitar sobrescrituras silenciosas. No hay garantía de transacción entre procesos concurrentes de localStorage; se recomienda una sola pestaña.

El historial para Deshacer vive en memoria y guarda un único conjunto anterior de tareas. El borrador de texto persiste con los datos. El service worker cachea solo recursos estáticos y no modifica localStorage. Exportación y restauración utilizan JSON validado.

`dates.mjs` valida fechas y convierte la hora local al instante del aviso. `reminders.mjs` solicita permiso mediante una pulsación explícita, verifica la versión del receptor, sincroniza horarios y refleja errores. El secreto aleatorio de cada navegador queda en localStorage fuera de exportaciones; el Worker deriva un identificador SHA-256 y dirige la petición a un Durable Object de ese dispositivo. El servidor guarda horarios, suscripción y estado de envío. Alarmas de Durable Objects despiertan el servicio sin depender de una pestaña abierta. Las peticiones validan origen, autorización, límites y destino Web Push; las credenciales VAPID son secretos propios.

Un espejo local en IndexedDB sirve al receptor con la app cerrada. Las cargas push contienen solo identificador, instante y clave de deduplicación. La notificación utiliza el texto local, omite tareas completadas/retiradas/reprogramadas y registra la recepción. La reserva de deduplicación se hace en una transacción de IndexedDB y se revierte si falla la presentación. El envío puede repetirse tras una interrupción del servidor, por lo que el receptor y la etiqueta también evitan duplicados visibles. Los intentos fallidos se reintentan hasta seis veces; suscripciones 404/410 se eliminan. Un envío aceptado por el proveedor no demuestra recepción física.
